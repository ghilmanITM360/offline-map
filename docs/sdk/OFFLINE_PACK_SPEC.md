# Offline venue pack v1 — implemented subset and the proposal behind it

## Implemented (C5, 2026-10-27)

Where this section and the proposal below differ, **this section is what the code does**.

- **Manifest** (`pack.manifest.json`, schema 1, strict JSON; parser `parsePackManifest`): `packId` (`<venueId>@<packVersion>`), `venueId`, `packVersion` (x.y.z), `sdkCompatibility` (bounded range such as `>=0.1.0 <0.2.0`), `routingPolicyVersion`, `createdAt`, `minimumPlatformCapabilities`, `bounds`, `languages`, `totalBytes`, `fileCount`, `resources[]` (`path`, `kind`, `bytes`, `sha256`), `attributions[]` (at least one), `provenance`; `keyId`/`signatureAlgorithm` only when signed. Resource records carry a `kind`, not a media `type`. Kinds: `map-archive`, `routing-graph`, `place-directory`, `gate-metadata`, `localization`, `provenance` (all required, one each) and `map-style` (optional). Scripts and native code are refused by extension whatever the `kind` says.
- **Data files** read by `parsePackVenueData`: `routing-graph` = `{schemaVersion:1, venueId, dataVersion, nodes:[{id,lat,lng}], edges:[{from,to,distanceM,weightMultiplier?}]}` (directed, in routing order); `place-directory` = `{schemaVersion:1, venueId, places:[{id,kind,nodeIds}]}`. Both are validated (finite WGS84 coordinates, positive distances, edges and places referencing only known nodes, no duplicate ids, no control characters) and served through Maps. `gate-metadata`, `localization` and `provenance` are venue-scoped JSON the SDK does not interpret; the compiler requires each to name the pack's venue.
- **Compiler** (`scripts/sdk-pack/compile.ts`, `compilePack(dir, spec, { write })`): output is a pure function of the files and the spec — resources sorted by path, 64 KiB streaming SHA-256, no clock (`createdAt` is the spec's), no host paths. It refuses symlinks anywhere, undeclared and missing files, unsafe/duplicate/case-colliding paths, unknown or missing kinds, malformed versions or ranges (including a range no SDK could satisfy), missing attribution/provenance, a pack id that is not `<venueId>@<packVersion>`, a data resource that names another venue, and a file that changes while it is hashed. The manifest is then re-verified by the SDK's own parser and `verifyPack` against the directory. It never signs.
- **Karachi pack** (`scripts/sdk-pack/karachi.ts`, `npm run sdk:karachi-pack -- <fresh-directory-outside-repository>`): `karachi-ijtema@1.0.0` from the tracked PMTiles archive (SHA-256 `d5e6883d…8cc0`) and the repository's V2 graph (303 nodes, 686 directed edges), 60 places (18 gates, 42 blocks), gate records and names. It adds and drops no connectivity: Gates 18 and 19 remain unconnected and `ground_truth_required`. The build is byte-reproducible and pinned in `scripts/sdk-pack/karachi-ijtema.pin.json`; the pin changes only by an explicit `--write-pin`. A second, synthetic pack (`scripts/sdk-pack/demo.ts`) exists so the sample app can show two isolated venues.
- **Store and manager**: `createFileSystemPackStore` over the small `PackFileSystem` port, plus `createPackManager` (install from staging, verify, atomic pointer, rollback, recovery, pins, storage check). Reference port implementations: Node (`scripts/sdk-pack/nodePackFileSystem.ts`) and Expo (`examples/expo-consumer/expoPackFileSystem.ts`). Installed directories are `packs/installed/<venueId>@<version>`; bundled ones live under a host-chosen id.
- **Hashing speed (C6)**: verification hashes every byte, in bounded 64 KiB chunks, in the SDK's own SHA-256 (no native dependency; rewritten without helper calls, about 30% faster in the Hermes interpreter, same digests, checked against Node's SHA-256 at every padding boundary). `createFileSystemPackStore({ digestFile })` is an optional port for a platform digest that is much faster than interpreted JS: it must read the file once and return the length and lowercase hex SHA-256 of exactly the bytes it hashed, or `null` to leave the file to the SDK's streaming hash (right for a file too large to hold in memory). A throw, a `null` or a malformed answer all fall back to streaming, and a damaged file still fails the manifest check, so the port can only make verification faster. The Expo example uses `expo-crypto` for files up to 8 MiB (`examples/expo-consumer/nativeDigest.ts`).
- **Trust**: an unsigned pack is `trust: none` until its manifest digest is pinned out of band (a bundled pack: the digest is built into the app) — integrity and consistency, not publisher authenticity. Installing an imported or downloaded pack requires a signature from a trusted key, and **no signing scheme, key or verifier exists yet**: imported and remote packs are refused. Nothing in this repository fabricates one.
- **Not implemented**: signing and key rotation, download/import UI, content-addressed directories, `map-style` consumption, compression-ratio budgets, a durability (fsync) guarantee beyond what the platform gives (expo-file-system offers no flush).

# Proposed offline venue pack v1 (original design)

Current data is executable TypeScript under src/data/ijtema, graph derived at import, OSM street graph generated and committed; DATA_MANIFEST.json hashes source. Current PMTiles installer verifies bundled size/SHA but has an Ijtema filename prefix and prunes older versions. Neither is a general signed pack installer. This proposal serializes data only, retains canonical IDs and surveyed facts, and replaces eager pruning with pin-aware retention.

## Manifest and payload

Proposed manifest fields: `schemaVersion:1`, `venueId`, SemVer `packVersion`, `sdkCompatibility` range, `routingPolicyVersion`, `createdAt`, `minimumPlatformCapabilities`, `bounds`, `languages`, `resources`, `attributions`, `provenance`, `keyId`, `signatureAlgorithm`. Resource record: relative `path`, media `type`, exact `bytes`, SHA-256; manifest has explicit total uncompressed bytes and file count. Payload allowlist: PMTiles v3; JSON local MapLibre style; JSON place directory/aliases/localized labels; validated graph nodes/edges/geometries/connectors/entry policies; local glyph/sprite images if used. No JS/TS/WASM/scripts/native binaries, dynamic expressions beyond allowlisted MapLibre style operators, plugin code or executable hooks.

Current Block/Gate/Rasta IDs remain exact (for example B2, GATE_12); venue namespace prevents cross-venue collisions. Encode coordinate system WGS84 degrees explicitly, directed pedestrian edges and restrictions, surveyed/needs-verification status, truthful outside-coverage boundaries, provenance and unavailable gate reasons. Never infer new connectors from missing fields. Compiler converts current source to versioned JSON with deterministic roundtrip parity tests. Preserve semantic instruction tokens; UI labels stay data, not translated routing logic.

Proposed trust format: detached Ed25519 signature of the exact UTF-8 manifest bytes, with strict parser rejecting duplicate JSON keys/non-finite numbers/unknown critical fields. No JSON reserialization at verification. Manifest hashes every resource; file names sorted for deterministic creation but signature covers exact bytes. Trust roots ship with app/SDK configuration, not inside untrusted pack. Signed key rotation must be authorized by an existing trusted root; unknown key/signature fails closed. Cryptographic implementation/library selection, key custody, rotation/revocation and distribution operator require reviewed B9 spike/owner approval; no homegrown cryptography. Checksums alone do not establish publisher authenticity.

## Install transaction

1. Accept bundled source, optional HTTPS download, or explicit offline file import. Never auto-fetch to open an installed venue. Download uses bounded bytes/time, constrained redirects and cancellation; imported files are equally untrusted.
2. Check compatibility/schema/capabilities and trust before activation; stream into private staging without loading whole archive into JS memory. Enforce compressed/uncompressed/per-file/PMTiles-header size, count, nesting and compression-ratio budgets. Numeric initial budgets remain approval inputs, never unlimited defaults.
3. Reject absolute/drive/UNC paths, `..`, NULs, ambiguous separators/Unicode collisions, duplicate/case-colliding names, symlinks/hardlinks/devices, encrypted/nested archives, unknown resource types, missing or extra files. Extract only within staging realpath. Restrict style URLs to pack-relative verified files; ban remote tiles/glyphs/sprites/imports. No network authority from a signed style alone.
4. Verify signature, all resource hashes, graph topology/IDs/bounds/connectors, language completeness, PMTiles ranges and SDK contract. Disk reserve includes current active pack + last-known-good + full staging + overhead; insufficient space returns actionable error without touching active data.
5. Atomically rename verified staging into immutable content-addressed pack directory; atomically journal active pointer only after durable writes/validation. Recover from crash before/after either rename deterministically. Filesystem durability/rename semantics need platform-specific proof.
6. Active journey pins exact venue/pack/policy and keeps read-only handles. New pack becomes default only for next journey after cancellation/exit; no mid-route graph switch. At least one last-known-good pack retained. Garbage collect only unpinned inactive versions after successful activation and retention policy; never delete active/LKG for space reclamation.
7. Roll back failed activation to previous pointer; incompatible pack stays rejected. Unsupported schema needs reviewed data migration creating a new verified artifact, never mutation of a signed pack. Reject downgrade below signed minimum policy floor, with explicit authorized emergency rollback channel; offline expiry/revocation cannot pretend to know server state. Installed usable pack should not expire navigation merely because internet is absent; owner policy must settle safety-critical withdrawal behavior.

## Offline boundary

When required compatible pack exists, map/directory/internal routing/manual guide/language changes/qualified GPS guidance work without servers, authentication or remote geocoding. External Google walking proxy remains optional; bundled OSM coverage or clearly labelled direct guide handles failure. A direct guide is not a surveyed walking route. MapLibre OfflineManager network tile packs are not this signed local PMTiles installation mechanism. A disconnected device receives no update until optional connectivity or explicit file transfer. Executable SDK/native updates follow app release policies separately; no executable OTA is designed here.

Attribution/provenance is visible in both apps and exported with packs. Preserve current OSM ODbL and MapLibre license notices; owner/legal review determines redistribution obligations for each dataset, not speculative legal text. No credentials, consent state or user GPS history in venue packs.

Pack generation requires a new, nonexistent output directory outside the repository. Existing directories (even empty ones), symlink destinations/ancestors and dot-segment aliases are refused. Use a fresh child of a temporary directory for each generation; the generator never deletes or replaces existing output. Failed generation may leave its own partial output for inspection.
